# 可用性測試腳本

設計者：jimmy0117　　　　雛型網址：https://jimmy0117.github.io/report-system-design/ （也可以直接開啟 `index.html`）

> 測試前，主持人重新整理頁面，讓資料回到初始狀態，並確認頂欄身分是「醫師甲」。任務 3 開始前，由主持人把頂欄身分切換成「放射師」（切換身分只是雛型的測試功能，不算在任務裡）。

## 測試前說明（約 1 分鐘）

> 謝謝你協助測試。我們測試的是設計，不是你，遇到困難代表設計需要改進。請想像你是一位一天要打幾十份報告的醫師，邊操作邊說出你在想什麼、在找什麼。我在過程中不會提示操作方式，找不到的話直接說找不到就好。報告內容不用寫得正確，可以隨意輸入或使用系統提供的句子。

## 測試任務

任務要描述醫師的工作情境，不能提示操作方式。三個任務合計約 10 分鐘內可完成，至少一個任務與你的設計變數有關。

| 任務 | 任務描述（念給測試者聽） | 成功標準 | 與設計變數相關 |
| --- | --- | --- | --- |
| 1 | 「團檢的胸部X光很多，大部分都是正常的。請用最快的方式把你今天的胸部X光報告都簽發掉，但每一份你都要確認過。」 | 使用批次功能（勾選 → 帶入正常範本 → 逐筆確認），R0001、R0010 都變成已認證；記錄是否注意到每份的影像、是否發現可以批次 | 是（變數五） |
| 2 | 「接下來，請把今天其他指派給你、還沒打的報告全部完成，完成到你覺得今天的工作做完為止。」 | R0002 儲存或認證；未完成數量歸零；沒有替已 DC 的 R0004 打報告；記錄回清單的次數 | 否 |
| 3 | 「你現在是放射師。有一份心臟超音波還沒有醫師負責，請交給醫師甲。另外有一份胸部X光還沒有影像，請處理到它也有醫師負責。」 | R0006 指派給醫師甲；R0009 先取回影像再指派；過程中沒有把放射師的操作和醫師的畫面搞混 | 是（變數六） |

好的任務：「請完成今天指派給你、還沒打的胸部X光報告。」
不好的任務：「請點選上方的篩選按鈕，選擇胸部X光。」（把操作方式告訴了測試者）

## 測試後訪談問題

1. 批次簽發時，每份還要看過影像、按一次確認，你覺得這樣夠快嗎？如果可以一次全部簽發，你會用嗎？為什麼？（變數五的取捨）
2. 切換成放射師後，你覺得這個畫面跟醫師的畫面是「同一個」還是「不同的」？有沒有哪裡讓你搞混？（變數六：同一畫面、依角色區隔）
3. 「儲存」和「認證」這兩個按鈕，你覺得差別是什麼？什麼時候會按哪一個？（對應啟發式評估 H8：用語未經醫師確認）

## 自我檢查

- [x] 任務描述的是工作情境，沒有洩漏操作方式（任務 1 說「最快的方式」但沒有提到勾選或批次；任務 3 沒有提到「指派」「取回影像」按鈕）
- [x] 至少一個任務與設計變數有關（任務 1：變數五；任務 3：變數六）
- [x] 三個任務能在 10 分鐘內完成（以腳本實際操作確認流程可行；真人時間要在試測時確認）
- [x] 每個任務都有明確的成功標準
